# Вход через Яндекс

## Подключение

Compas использует отдельное приложение Яндекс OAuth. Client ID и Client Secret задаются в `.env`. Локальный адрес возврата: `http://127.0.0.1:8001/yandex/callback/code`.

1. Создайте **отдельное приложение Compas для авторизации пользователей** в [Яндекс OAuth](https://oauth.yandex.ru/client/new/id/).
2. Платформа: «Веб-сервисы». Для локального запуска Redirect URI должен точно соответствовать:

   `http://127.0.0.1:8001/yandex/callback/code`

3. Запросите разрешения «Адрес электронной почты» (`login:email`) и «Логин, имя и фамилия, пол» (`login:info`).
4. В локальном `.env` заполните:

   ```dotenv
   YANDEX_CLIENT_ID=идентификатор_нового_приложения
   YANDEX_CLIENT_SECRET=секрет_нового_приложения
   YANDEX_REDIRECT_URI=http://127.0.0.1:8001/yandex/callback/code
   ```

5. После заполнения перезапустите API. Для HTTPS-развёртывания замените URI в настройках Яндекса и `.env` одновременно и включите `COOKIE_SECURE=true`.

Не переносите весь `.env` другого проекта: настройки БД и JWT-ключи Compas должны оставаться независимыми. Секреты не должны попадать в Git или сообщения. Пока OAuth-настройки пустые, ручки видны в Swagger, но начало входа вернёт 503 с объяснением.

Официальные инструкции: [регистрация приложения](https://yandex.ru/dev/id/doc/ru/register-auth), [обмен кода и PKCE](https://yandex.ru/dev/id/doc/ru/codes/code-url), [профиль пользователя](https://yandex.ru/dev/id/doc/ru/user-information).

## Ручки

| Метод и адрес | Что делает |
|---|---|
| `GET /yandex/login` | Начинает вход: перенаправляет в Яндекс, создаёт state и PKCE |
| `GET /yandex/callback/code` | Принимает code и state, проверяет cookie, обменивает код, выполняет вход |
| `POST /yandex/callback/token` | Вход по уже полученному OAuth-токену из JSON `{"token":"..."}` |
| `POST /yandex/link` | Привязывает Яндекс к текущему авторизованному аккаунту, JSON такой же |

Успешный вход возвращает `access_token` и `refresh_token` Compas и устанавливает его cookie. Токены Яндекса в ответ не возвращаются, не сохраняются в БД и не записываются в логи.

При заданном `FRONTEND_URL` callback устанавливает cookie и перенаправляет на этот адрес. Без настройки возвращается JSON с токенами. Параметры запроса не могут изменить адрес перехода. Для текущего фронта включите `LEGACY_AUTH_COOKIES=true`; настройка связки описана в [frontend-integration.md](frontend-integration.md).

## Аккаунты

Новый пользователь создаётся с ролью `user=1`. Повторный вход определяется по уникальному `yandex_id`, а не по изменяемому имени или email; роль и данные существующего профиля сохраняются.

Если email уже зарегистрирован обычным способом, автоматического объединения нет. Сначала войдите в этот аккаунт, затем выполните `POST /yandex/link` с токеном Яндекса того же email. После привязки можно входить через Яндекс без дубликатов профиля. Привязка чужого или другого уже привязанного ID отклоняется.

Аккаунт, созданный только через Яндекс, не имеет пароля. Попытка входа с произвольным паролем возвращает отказ, а не ошибку сервера. Добавление пароля доступно через существующий сценарий восстановления при настроенном SMTP.

## Проверка

В Swagger проверьте наличие секции «Авторизация Яндекс». Для реального перехода откройте `http://127.0.0.1:8001/yandex/login` **в адресной строке браузера**: Swagger Execute не предназначен для переходов на страницу согласия другого сайта.

`POST /yandex/callback/token` принимает токен в JSON. В отличие от старого проекта, `GET /yandex/callback/token?token=...` не поддерживается: токен в URL мог бы попасть в историю браузера и журналы доступа.

При входе и callback используйте один хост. Если начали с `127.0.0.1`, не заменяйте его на `localhost`: cookie состояния относится к хосту начала входа.

Автотесты проверяют state/PKCE, обработку отказов и ошибок провайдера, создание и повторный вход, привязку и сохранение прав. Они используют подменённые ответы Яндекса и не заменяют проверку живого входа после регистрации приложения.
