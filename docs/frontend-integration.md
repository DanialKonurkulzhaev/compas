# Подключение фронта

Проверено с `borowskixd/odeyalo-clinical-compass`, ветка `main`, коммит `aeca90d734db8093be7cd092b81c881ea8e2e7cf`.

## Бэкенд

```powershell
docker compose -f docker-compose.init.yml run --rm init
docker compose up -d --build
```

Настройки нового `.env` рассчитаны на фронт http://localhost:3000 и API http://localhost:8001. Если `.env` уже существует, добавьте вручную:

```dotenv
LEGACY_AUTH_COOKIES=true
FRONTEND_URL=http://localhost:3000
ALLOWED_ORIGINS=["http://localhost:3000","http://127.0.0.1:3000"]
```

Затем пересоздайте приложение: `docker compose up -d --build`. Остальные ключи менять не нужно. Не используйте `down -v` для обновления.

Бэкенд принимает `access_token` в режиме совместимости, но проверяет подпись собственным ключом Compas и существование пользователя в БД. Cookie `compas_access_token` имеет приоритет. При входе, обновлении и выходе обрабатываются оба набора cookie. Для отдельного Swagger можно поставить `LEGACY_AUTH_COOKIES=false`; не используйте «Одеяло» и Compas на одном browser-host одновременно в режиме совместимости.

Регистрация возвращает профиль и токены. Пароль и его хеш не возвращаются. Ручка `/client/get_your_psychologist` возвращает `items` только с подтверждёнными психологами текущего пользователя. Роль психолога по-прежнему назначается отдельно; заполнение анкеты не повышает права.

## Фронтенд

Одного обновления бэка недостаточно. В исходном фронте production-адреса указывают на «Одеяло», нет опубликованного порта, а BFF отправляет `cookies.toString()` вместо cookie запроса.

Файл [frontend-compas.patch](frontend-compas.patch) содержит минимальные изменения фронта. Он подготовлен для указанного коммита; чужие последующие правки сначала проверьте. В корне фронтенд-репозитория:

```powershell
git apply --check C:/path/to/compas/docs/frontend-compas.patch
git apply C:/path/to/compas/docs/frontend-compas.patch
docker compose -f deploy/docker/docker-compose.yml up -d --build
```

Путь в первых двух командах замените на фактический. Бэкенд к этому моменту должен быть запущен.

Патч:

- публикует фронт на localhost:3000 и подключает к существующей сети `compas_default`;
- задаёт браузерные адреса API localhost:8001 и BFF localhost:3000/api на этапе сборки;
- задаёт внутренний адрес API `http://compas-api` и BFF `http://127.0.0.1:3000/api` для Node.js;
- исправляет пересылку cookie и убирает обмен кода Яндекса без state в middleware;
- использует отдельные имена контейнеров и образа nginx фронта.

`NEXT_PUBLIC_*` в Next.js попадают в браузерную сборку. При смене публичного адреса требуется пересборка фронта. `localhost` внутри контейнера не указывает на другой контейнер. Бэкенд публикует отдельные DNS-имена `compas-api` для nginx и `compas-backend` для API, чтобы два сервиса `app` не конфликтовали в общей сети.

## Яндекс

В приложении Яндекса зарегистрируйте callback `http://localhost:8001/yandex/callback/code` и укажите тот же `YANDEX_REDIRECT_URI` в `.env`. Если уже зарегистрирован `127.0.0.1`, можно оставить его, но фронт и начало OAuth тоже нужно открывать через `127.0.0.1`.

Callback обрабатывает бэкенд: проверяет state и PKCE, устанавливает cookie и перенаправляет на `FRONTEND_URL`. В URL перехода нет кода или токенов. Если `FRONTEND_URL` не задан, сохраняется прежний JSON-ответ для Swagger. Вход без настройки OAuth вернёт 503; обычная регистрация и вход доступны.

## Проверено

- Подготовка `.env` через Docker в отдельной копии проекта без локальных зависимостей, миграции на пустом PostgreSQL 18 и автоматическая загрузка 13 тестов.
- Production-сборка фронта с патчем, запуск Next.js и nginx в общей сети с новым бэкендом.
- Через HTTP-ручки реального BFF: регистрация, вход, чтение профиля, каталог тестов, список психологов, «мои психологи», серверная страница `/profile` и выход.
- Через BFF получены вопросы Бека, сохранены два прохождения, прочитана история из двух результатов; в списке пройденных тестов осталась одна карточка.
- Проверки backend-контрактов, включая обмен refresh-токена и OAuth-переход, входят в `tests/test_frontend_compat.py`.

Это проверка HTTP-взаимодействия; все формы и переходы в браузере ещё не проверялись. Живой OAuth в этой связке требует настроенного приложения Яндекса. В исходном фронте остаются `/manager/give_task` и `/auth/burnout_calculate`, которых нет в выделенном Compas: эти функции нужно отдельно согласовать или убрать из интерфейса. Проверки доступа на бэкенде не отключались.
